# 쿠팡 실시간 핫딜 봇

쿠팡 상품 가격을 지속 추적해 **평소보다 급락한 상품**과 **당일 골드박스 특가**를
텔레그램 채널에 자동으로 올립니다.

## 구조

| 파일 | 역할 |
|---|---|
| `config.py` | 모든 조절값. 튜닝은 여기만 |
| `coupang.py` | 쿠팡 파트너스 API (HMAC 인증) |
| `store.py` | 가격 이력 DB (SQLite) |
| `scoring.py` | 하드컷 → 점수 → 등급 |
| `notify.py` | 텔레그램 카드 발송 |
| `main.py` | 실행 진입점 |
| `calibrate.py` | 임계값 조정용 히스토그램 |
| `.github/workflows/bot.yml` | 자동 실행 스케줄 |

## 실행 모드

| 모드 | 동작 |
|---|---|
| `watch` | **★ 실시간 상주 감시.** 러너를 켜둔 채 3분마다 순회, 급락 시 즉시 발송 |
| `auto` | 1회 실행. 시각 보고 데일리/급락 자동 선택 (Private용) |
| `selftest` | 쿠팡·텔레그램 연결만 점검 |
| `hunt` | 급락 감시만. 없으면 발송 안 함 |
| `live` | 데일리 발송 (급락 + 골드박스) |
| `test` | 진단 리포트 (점수·배점 표시, 실발송 아님) |
| `dry` | 콘솔 출력만 |

## 워크플로 선택 — 둘 중 하나만 켜세요

| 파일 | 레포 | 방식 | 반응 속도 |
|---|---|---|---|
| `watch.yml` | **Public 필수** | 상주 실행 | **3분** |
| `bot.yml` | Private 가능 | cron 20분 | 20~40분 |

**동시에 켜면 DB 충돌이 납니다.** 쓰지 않을 쪽은 반드시 삭제하세요.

## 발송 정책

| 구분 | 시각 | 내용 |
|---|---|---|
| **오늘의 핫딜** | KST **08:00 / 12:30 / 18:00 / 21:00** | 급락 + 핫딜을 **묶어서** 한 번에 |
| **가격 급락 포착** | 그 외 3분마다 감시 | 포착 시에만 **급락 건만** 즉시 발송 |

정기 시각에 급락이 있으면 그 발송에 합쳐집니다. 급락이 없으면 핫딜만 나갑니다.
시각은 `config.py`의 `DAILY_SLOTS`에서 바꿉니다. 안내문 문구도 자동으로 따라갑니다.

## 사용자에게 보이는 용어

'골드박스' 같은 내부 용어는 쓰지 않습니다. `config.py`에서 관리합니다.

| 상수 | 값 |
|---|---|
| `LABEL_DAILY` | 오늘의 핫딜 |
| `LABEL_CRASH` | 가격 급락 포착 |
| `LABEL_RISING` | 인기 급상승 |

## 인기 급상승 (🚀)

판매순위 이력을 쌓아 순위가 크게 뛴 상품에 배지를 붙입니다.

| 조건 | 기본값 |
|---|---|
| 상승폭 | `RISE_MIN_JUMP` 20계단 이상 |
| 현재 순위 | `RISE_MAX_RANK` 40위 이내 |
| 비교 기간 | `RISE_DAYS` 3일 |

하위권 요동(95위→70위)은 걸러집니다.

## 가격비교는 필수입니다

모든 카드에 반드시 비교가가 들어갑니다. 못 구하면 **그 상품은 발송하지 않습니다.**

| 우선순위 | 출처 | 표시 라벨 |
|---|---|---|
| 1 | 쿠팡 API 정상가 | `정상가` |
| 2 | 자체 이력 최근 14일 최고가 (표본 2개↑) | `최근 최고가` |
| 3 | 쿠팡 할인율로 역산 | `정상가` |
| — | 셋 다 없거나 차이 3% 미만 | **발송 제외** |

`config.py`의 `REF_MIN_POINTS`(기본 2)와 `REF_MIN_GAP`(기본 0.03)로 조절합니다.

## 필요한 Secrets

Settings → Secrets and variables → Actions → Secrets

| 이름 |
|---|
| `COUPANG_ACCESS_KEY` |
| `COUPANG_SECRET_KEY` |
| `TELEGRAM_BOT_TOKEN` |
| `TELEGRAM_CHAT_ID` |

> 네이버 키는 더 이상 쓰지 않습니다. `NAVER_*` 시크릿은 남아 있어도 무해합니다.
> `RUN_MODE` 변수도 더 이상 쓰지 않습니다 (`auto`가 대체).

## 판정 방식

기준가 = **그 상품 자신의 최근 14일 가격 중앙값**

| 항목 | 배점 |
|---|---|
| 하락폭 | 40 |
| 자릿수 오류 (`현재가 × 10 ≈ 평소가`) | 20 |
| 판매 인기도 (rank) | 15 |
| 절대 하락액 | 10 |
| 로켓배송 | 8 |
| 골드박스 | 7 |
| 표본 부족 / 수량표기 없음 | −12 / −8 |

발송 게이트: 하락률 30% 이상 **AND** 하락액 15,000원 이상

| 등급 | 조건 |
|---|---|
| S | 82점↑ + 자릿수 오류 → 🚨 가격오류 의심 |
| A | 68점↑ |
| B | 48점↑ (데일리 발송에만 포함) |

## 초기 운영

| 시점 | 상태 |
|---|---|
| 설치 직후 | 골드박스만 발송. 급락은 "이력축적중" |
| **약 6시간 뒤** | 급락 판정 시작 (표본 6개 도달) |
| 약 1일 뒤 | 표본부족 감점 해제, 등급 정상화 |
| 1주 뒤 | `python calibrate.py`로 임계값 조정 |

## 튜닝

`config.py`의 값만 고칩니다.

| 값 | 기본 | 효과 |
|---|---|---|
| `SEND_RATIO` | 0.70 | 낮추면 알림 줄고 정확해짐 |
| `MIN_SAVING` | 15000 | 올리면 소액 딜 제외 |
| `GOLDBOX_SHOW` | 6 | 데일리 골드박스 개수 |
| `HUNT_MAX_CARDS` | 4 | 급락 1회 최대 알림 수 |
| `GRADE_B` | 48 | 낮추면 발송 늘어남 |

한 번에 값 하나씩만 바꾸세요.
